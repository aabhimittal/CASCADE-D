      Measured on held-out data

      For each dataset, a threshold is chosen on 500 examples so that, with 95% confidence, the error of what d1 answers stays under the target. It is then measured on the other 500. Ten random splits; mean ± spread.

      The thresholds come from Learn-then-Test: every candidate threshold is a statistical test, corrected for how many were tried. Where a target can't be guaranteed from 500 examples, no threshold is picked and d1 answers nothing.

      How a request moves through the cascade

      1. The decision model (d1-3B, about 10 ms on a GPU) reads the request and gives a probability for every option. If its top option clears the threshold, that is the answer.
      2. Otherwise a small LLM answers the same typed question. Its confidence comes from token probabilities, calibrated on validation data, not from what it says about itself.
      3. Whatever is still uncertain goes to a large LLM, which always answers.

      Thresholds are chosen per target error: you say how many mistakes you can live with, and the optimizer finds the cheapest cascade that stays under it.

      What has not been measured yet

      The LLM tiers have not been run on real data, because that needs API keys. So the headline question, whether adding d1 makes the whole cascade cheaper than an LLM-only cascade at the same error, is still open. The full cascade report on synthetic data shows what that answer will look like.

      On synthetic data, d1 only pays off when it is good enough: with tier-0 error around 15% the cascade is 15–46% cheaper than LLM-only, with 34% error it costs more.
